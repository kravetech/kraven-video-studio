# Video production workflow

Part of **Kraven Video Studio** — You shoot. AI edits. You approve.

Start through `Start-Video-Studio.cmd` and invoke `/video-studio`. For manual commands, dot-source `. .\Start-Video-Studio.ps1 -Shell`. Use the human reviewer from `studio.local.json`; never run approval/release commands without explicit human consent.

1. **Analyze.** Preserve the recording, inspect framing and listen to the audio. Read the full transcript before selecting the hook. `pnpm cover:frames <video>` makes a contact sheet; `ffmpeg -i <video> -af ebur128 -f null -` measures loudness.
2. **Transcribe.** `pnpm transcribe <video> public/samples/<name> tl` extracts 16 kHz mono audio, runs large-v3 word timing without VAD and writes captions needing review. Select another supported language when appropriate. `pnpm captions:show <captions.json>` prints phrases.
3. **Plan.** Write edit JSON with `source`, `profile` (`vertical-1080` or `horizontal-1080`), optional `fps`, `title`, and `segments: [{label,in,out,words,zoom,punch,alternate}]`. Optional `color`/`voice` are FFmpeg filter chains; apply only after assessing the recording. Preserve meaning and natural delivery. Do not invent claims or drop negations.
4. **Assemble.** Run `pnpm preflight <edit.json> public/samples/<name>-master.mp4`, then `node scripts/assemble-cut.mjs <edit.json> public/samples/<name>-master.mp4`. Output follows the selected profile; loudness target is -16 LUFS with -1.5 dB true peak. The source frame rate is the default. Set `frameRateConversion: true` with `fps` only after reviewing an intentional conversion. Different source/output orientations require explicit `framing: { mode: "fit" }` or reviewed `fill` framing.
5. **Verify.** Transcribe the assembled master and run `node scripts/verify-cut.mjs <edit.json> <master.captions.json>`. Investigate missing words. Do not weaken verification to conceal clipped speech.
6. **Preview.** Log corrections in `review.proposedCorrections`. Plan `callouts: []` and a `post` block in the edit file. Render `CaptionedClip` with a props JSON containing paths relative to `public`, `previewUnreviewed: true`, and the master's `fps`. SRT previews use `pnpm captions:srt <captions.json> out/<name>.srt --unreviewed`.
7. **Approve text.** Only after human confirmation, run `pnpm captions:approve <captions.json> <reviewer>`. Approval binds text and timing. Re-cuts require a new human sync check and `captions:approve-sync`. A CLI reviewer string is not independent authentication.
8. **Graphics.** `pnpm cover <clean-master> --title "ONE CLEAR IDEA" --at 2 --out "<package>/<name>-Cover.jpg"`; `--closeup` lowers the title. Horizontal packages use `pnpm thumbnail <clean-master> --title "ONE CLEAR IDEA" --at 2 --out "<package>/<name>-Thumbnail.jpg"`. Timed callouts use spoken copy. `pnpm broll <cues.json> [outDir]` accepts portrait/landscape ratio; choose cutaway timing manually and either place exported cards externally or use the timed `broll` cues described in [Enhancements](ENHANCEMENTS.md). The speaker's audio continues. Optional `zooms` and `sfx` use the same edited timeline.
9. **Package.** `pnpm render:final <master> <captions.json> --edit <edit.json> --out "<package>/<name>.mp4"`. Export SRT with `pnpm captions:srt <captions.json> "<package>/<name>.srt" --video "<package>/<name>.mp4"`. Vertical packages also use `pnpm post <edit.json> <captions.json> --out "<package>/<name> - post.txt"`. Retain ` - render.json` (generated by the full render), ` - project.json` and ` - editing summary.md`; cut packages also retain `.cuts.json` and `.edl`. The project record must declare `source`, `master`, `profile`, `fps` and positive measured `masterDurationSec`. Paths resolve from the project working directory; absolute paths may be used locally. Uncut packages omit `segments`. Basenames must match the package directory.
10. **Validate and release.** `pnpm validate "<package>" --captions <captions.json>` checks all required files, full decode, format, loudness and approved SRT. Human review of the actual deliverables is still required. Then `pnpm release "<package>" --approved-by <reviewer> --upload-dir "workspace/For Upload"` copies validated bytes with hashes. This never publishes to social media.

## Quality

Preserve the bundled graphics: uppercase white Geist captions, active-word box, stacked covers, restrained callouts and keynote B-roll. Do not smooth or alter faces. Measure a neutral surface before color changes; denoise only when audible noise warrants it. The source voice chain uses 80 Hz high-pass, light denoise/EQ and gentle compression when needed.

Review every cut boundary/callout, first/last caption, cover and complete audio. Cover text must clear the mouth. Keep one idea per cutaway and B-roll only where it clarifies the spoken content.

Full editing/captions/artwork/validation supports portrait 1080x1920 and landscape 1920x1080. Real-recording landscape acceptance remains pending. Standalone B-roll supports both aspect ratios. Cue-driven B-roll compositing is supported; cue selection remains manual. Intros/outros and publishing are not implemented. No external workspace is required.

## Revalidation and recovery

A full render records its master, captions, optional edit, rendering code and preset hashes. `--frames` is a test range and does not create a complete render record. Changed inputs require a fresh full render and validation. Validation also requires measured master duration and fingerprints the declared raw source. Approval of text alone does not establish source-to-master editing correctness.

Release stages and verifies all upload files before promotion. Previous upload folders are retained under `For Upload/.superseded/`. Never delete an active `.release.lock`. After a crashed process, inspect the destination, previous package and staged folder before removing a stale lock and retrying. Different destinations can release independently; unrelated applications are not constrained by this lock.


## B-roll validation and replacement

Standalone `pnpm broll <cues.json> [outDir] [--force]` checks all cues and destinations before writing. IDs use 1–80 letters/numbers/underscores/hyphens, begin with a letter or number, are unique ignoring case, and cannot be Windows device names. Path traversal, protected destinations, aliases escaping the selected folder and source collisions are refused. Existing clips and manifests require explicit `--force` approval, including in working folders; use a fresh output folder to retain an earlier batch.

Both standalone and embedded cards use the same content/timing rules. Use 1–5 primary words per part and at most 8 secondary words. Comparisons require exactly two nonempty parts; steps allow 1–3; AI workflows require 2–3 explicit nodes. Numeric cards require an explicit finite number. Stat cards require 0–100%; use `number` for other amounts. No missing content is supplied automatically.

Every card needs 900 ms of reading time after its final reveal, including delayed steps and supporting text. The minimum is calculated from the actual variant, text and motion clock; a short `holdMs` fails with the required value. No cue is extended or moved automatically. Existing default examples remain valid. Older short cues may need a manually reviewed longer hold and a fresh render/validation.

Audio targets and gain defaults come from the shared [audio standard](AUDIO-STANDARD.md); validate the final mix after adding effects.

## Current production policies

- Vertical videos burn captions into the picture; horizontal videos keep the picture clean. Both always deliver approved SRT. Transcript/synchronization approval is still required in both formats.
- Consider B-roll by default at the most important supported spoken moments. Use roughly one opportunity per 10–15 seconds of short-form or 15–30 seconds of long-form; this is a guide, never a quota. Skip filler/repeats and cards that add no explanation. Keep the spoken justification with each manually selected cue.
- Grade each recording independently. Do not copy a color chain from another take. YAVG is a diagnostic mean luma, not an exposure-quality threshold; inspect the face/subject, highlights, shadows, neutral reference, bit depth and range. Default to no unnecessary lift.
- Listen to every sound in the complete preview. Included whoosh/hit/tick defaults are 3/1/1; valid source WAVs and explicit existing cue volumes are retained.
- Cut-risk analysis is enforced during assembly, final rendering and package validation; release requires current successful QC. See [Cut QC](CUT-QC.md) for honest coverage, failures and explicit listening decisions. No test substitutes for listening to cuts.
- Caption conversion performs bounded positive timing repairs after pause snapping and logs original/repaired offsets. Machine output remains needs-review. Supply --audio for measured media bounds; --duration-ms is an explicit alternative, and transcript-max-offset is a labeled fallback. Impossible/invalid timing fails instead of dropping words.

## Required editorial reviews

Read docs/EDITORIAL-REVIEW.md. Run takes:review on the original Whisper JSON and 16 kHz mono WAV, with --source naming the actual source video. Selected ranges must cover the segments and snap margins. Every candidate needs a reasoned decision. Assembly requires current takeReview/takeDecisions; unresolved review cases may stay in a preview but block final rendering. Single-word repetitions are candidates, never automatic removals.

After the final render, run pacing:review on that encoded video and its captions, with --edit naming the rendered cues. Inspect the whole preview, including camera repositioning, noisy wordless gaps, readability and sound balance. Record truthful visualReview notes and decisions. The package project must name pacingReview/pacingDecisions. Validation and release require current resolved evidence. Never create human approvals on the owner's behalf. Edited timings require rebuilding/transcription/sync review and retimed enhancements, not surgery on an exported file.

Earlier media and review records are historical and remain unchanged. Regenerate editorial evidence for each new job. The scripts do not call a cloud model, automatically judge intent or publish.

For project-specific product names or acronyms, set `verify.exactWords` to an array of single words in private edit JSON. Those words require exact transcript matching unless an explicit `verify.variants` mapping is supplied. No private vocabulary is shipped in source.
